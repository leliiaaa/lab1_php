# BookSwap — Архітектура веб-системи обміну книгами

## Предметна галузь та характеристики системи
- **Призначення:** веб-платформа для обміну та тимчасового читання паперових книг між читачами (буккросинг / P2P-бібліотека).
- **Актори:** Guest, Reader, Administrator.
- **Архітектура:** MVC (PHP / Laravel, Eloquent ORM, Blade).
- **Основні сутності та таблиці БД:** `users`, `reader_profiles`, `categories`, `books`, `book_copies`, `wishlists`, `wishlist_items`, `exchange_requests`, `delivery_details`, `reviews`, `disputes`.
- **Вихідні дані:** каталог доступних примірників, реєстр обмінів, персональна статистика читача, адміністративні звіти.

## Повний Use Case: Request Book Exchange
- **Scope / Level:** BookSwap Online Platform / User-goal
- **Primary Actor:** Reader
- **Зацікавлені сторони:** читач-ініціатор, власник примірника, адміністратор платформи
- **Передумови:** користувач авторизований, обліковий запис не заблокований, відсутні прострочені повернення
- **Гарантія успіху:** запит на обмін та деталі доставки збережено, примірник зарезервовано, власнику надіслано сповіщення
- **Головний успішний сценарій:**
  1. Читач авторизується на платформі.
  2. Відкриває каталог книг.
  3. Вводить назву або автора в пошук.
  4. Фільтрує результати за жанром, містом, станом примірника та типом угоди.
  5. Відкриває сторінку видання.
  6. Переглядає опис та доступні примірники від різних власників.
  7. Обирає конкретний примірник.
  8. Натискає «Запросити обмін».
  9. Система перевіряє статус примірника (`available`) та ліміт активних запитів.
  10. Система відкриває форму оформлення запиту.
  11. Читач обирає тип взаємодії (тимчасове читання, зустрічний обмін або дарування).
  12. Обирає спосіб доставки (пошта або особиста зустріч).
  13. Вказує адресу/відділення та повідомлення власнику.
  14. Система перевіряє коректність даних доставки.
  15. Читач підтверджує відправку запиту.
  16. Система створює запис `ExchangeRequest` (`pending`), зберігає `DeliveryDetail` і переводить `BookCopy` у статус `reserved`.
  17. Система надсилає сповіщення власнику.
  18. Читач бачить підтвердження та переходить у «Мої обміни».
- **Альтернативні сценарії:**
  - А1: усі примірники зайняті — пропозиція додати у Wishlist.
  - А2: примірник щойно зарезервували — блокування оформлення та оновлення списку.
  - А3: перевищено ліміт активних неповернених книг — відхилення запиту.
  - А4: обрано зустрічний обмін — вибір власної вільної книги на заміну.
  - А5: некоректні дані доставки — запит на виправлення полів.
  - А6: помилка збереження в БД — відкат транзакції, статус залишається `available`.
